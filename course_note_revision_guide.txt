3.11 Пункт 4.3 "Механизм подбора кандидатов и формула совместимости"

Этот пункт стоит заменить целиком, потому что он является одной из сильнейших частей проекта.

Новый текст:

"Подбор кандидатов является одной из ключевых функций сервиса. Его задача заключается в формировании списка пользователей, которые могут быть потенциально интересны текущему участнику системы. В отличие от многих коммерческих решений, где принципы выдачи скрыты, в проекте Synxo алгоритм подбора построен прозрачно и опирается на формально определённые критерии.

Работа механизма подбора состоит из нескольких последовательных этапов. Сначала система получает профиль текущего пользователя и формирует пул кандидатов на уровне запроса к базе данных. Из рассмотрения исключаются собственный профиль пользователя, скрытые анкеты `GHOST_MODE` и профили `LIGHT_TALK`, если они давно не были активны. Дополнительно в выборку включаются только пользователи, у которых имеется хотя бы один общий интерес с текущим участником системы. Такой подход позволяет отсечь заведомо нерелевантные анкеты ещё до этапа ранжирования.

После этого к кандидатам применяется объектное поведение профиля через механизм состояния. На практике это означает, что итоговая видимость профиля определяется не внешними условными операторами, а логикой соответствующего состояния профиля.

Следующий этап — численная оценка совместимости. Для каждого кандидата рассчитываются пять частных факторов:
1. `F1` — оценка по общим интересам;
2. `F2` — оценка по расстоянию;
3. `F3` — оценка совпадения намерений знакомства;
4. `F4` — оценка недавней активности;
5. `F5` — социальный показатель.

Итоговый балл рассчитывается по формуле:

S = (W1 * F1 + W2 * F2 + W3 * F3 + W4 * F4 + W5 * F5) / (W1 + W2 + W3 + W4 + W5).

Каждый фактор приводится к шкале от 0 до 100. Оценка по интересам вычисляется как отношение числа общих интересов к общему количеству уникальных интересов двух пользователей. Такой подход делает метрику более корректной, чем простое сравнение абсолютного числа совпадений. Оценка по расстоянию убывает по экспоненциальному закону, что позволяет учитывать географическую близость без жёстких порогов. Оценка совпадения намерений знакомства строится на пересечении специальных интересов, отражающих формат общения. Оценка активности зависит от времени последней активности кандидата. Социальный показатель усиливает результат, если между пользователями уже есть встречный интерес.

В проекте предусмотрены две стратегии ранжирования. Для режима `RECOMMENDATION` используются веса `(45, 15, 20, 10, 10)`, то есть основной акцент делается на общих интересах. Для режима `PROXIMITY` используются веса `(25, 45, 15, 5, 10)`, где больший приоритет получает расстояние. При этом в профиле пользователя можно включить персональные настройки алгоритма и задать собственные веса факторов. В таком случае стандартные значения стратегии заменяются пользовательскими приоритетами.

После вычисления оценки совместимости кандидаты сортируются и отображаются пользователю в виде ленты. В интерфейсе показываются итоговый процент совместимости, расстояние, общие интересы и блок `Почему вы совпали`, содержащий короткое текстовое объяснение результата. Во внутренней модели и REST-ответе при этом также сохраняются частные оценки по отдельным факторам, что делает систему удобной для тестирования и последующего расширения.
